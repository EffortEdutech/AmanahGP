# Mosque And Surau Pilot Onboarding

Purpose: onboard selected mosque/surau organisations into the MAIN/JAIN pilot while keeping organisation-private operations protected.

## Pilot Entry Criteria

Each organisation should have:

- an approved organisation profile in `organizations`;
- active organisation administrators;
- reporting period and state policy confirmed;
- evidence owners identified;
- finance/reporting contact confirmed;
- support contact channel agreed.

## Onboarding Steps

1. Confirm the organisation profile uses the canonical `public.organizations` record.
2. Add the organisation to the pilot cohort using `pilot_cohort_organizations`.
3. Confirm the organisation appears in Authority View Organisation Registry.
4. Walk the organisation admin through monthly report preparation in AmanahOS.
5. Explain which evidence can be linked as authority-reviewable.
6. Confirm private documents and internal ledger details remain organisation-private unless summarised or explicitly linked through the authority evidence boundary.
7. Run a test submission using pilot data.
8. Confirm the submission appears in Authority View Submission Monitor.

## Organisation Briefing Points

- Authority View receives oversight metadata, submissions, obligations, exceptions, evidence links, state report packs, and KPI summaries.
- Authority View does not automatically expose internal ledgers, payment request details, bank account records, private documents, or raw evidence files.
- Clarification requests and corrective actions should be answered through the agreed pilot workflow.
- Any suspected wrong access must be escalated immediately using the access revocation/incident runbook.

## Exit Criteria

- Organisation can submit a monthly report.
- Authority can review the submission.
- Evidence boundary is understood by both parties.
- Pilot support contact is known.
- KPI and feedback capture are ready.
